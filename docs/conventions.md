# 维护约定

## 范围与唯一来源

- 每个 Skill 保留独立来源仓库；工具项目内附带的 Skill 可以登记子目录。
- `registry.json` 是目录元数据的唯一来源；README 自动生成。不引入源码副本或 submodule。
- 原创、fork、第三方必须区分。账户拥有仓库不代表原创；未审查时标记 `owner-repository-authorship-unreviewed`。
- `observed_commit` 是盘点时看到的提交，不是自动安装锁文件或“最新版本”承诺。
- 来源检查、单元测试、真实运行验证分别记录。`runtime_verified_at: null` 表示未记录真实运行验证。
- 不记录 token、密码、真实服务器凭据、任务日志或账号配置；私有仓库也不是密钥库。

## 新增或更新

1. 审查来源文件与敏感信息；运行适用测试，说明 mock 与真实验证边界。
2. 在独立仓库提交、发布；新仓库可见性必须明确，未明确时默认 private。
3. 更新登记表中的仓库、Skill 路径、分类、来源可见性和观测提交。
4. 执行 `python3 scripts/catalog.py` 和 `python3 scripts/catalog.py --check`。
5. 追加 CHANGELOG；经任务授权后提交与推送。

## 安装与同步

本仓库目前只索引，不自动安装或更新。安装目录不是作者身份依据；软链接应解析后去重。后续同步工具必须先检查本地改动，不得覆盖未提交内容。

## 与个人 Wiki 分工

Registry 记录资产与验证状态；个人 Wiki 记录方法、经验、比较和跨来源分析。双方通过链接关联，不复制维护完整目录。
